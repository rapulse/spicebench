# Wiki: Спецификация MCP-инструментов (`packages/mcp`)

## Принципы API для агентов
- Все ответы возвращают валидный JSON с предсказуемой структурой `{ ok: boolean, data?, error?: 
{ code, message, elementIds? } }`.
- Любая мутация схемы проходит через `CircuitController` (`packages/core`), попадает в стек 
Undo/Redo и рассылает событие обновления в GUI.

## Базовый набор инструментов (Фаза 3)
1. `get_circuit_state()` — возвращает текущий JSON-граф схемы и статус симуляции.
2. `place_component({ type, label?, params, x, y, rotation? })` — добавляет компонент на сетку.
3. `update_component({ id, params?, x?, y?, rotation? })` — изменяет номинал, положение или 
поворот.
4. `remove_component({ id })` — удаляет компонент и подключённые к нему провода.
5. `connect_pins({ from: { componentId, pinId }, to: { componentId, pinId } })` — прокладывает 
ортогональный провод между выводами.
6. `validate_circuit()` — проверяет топологию без запуска SPICE; возвращает список 
предупреждений и ошибок с ID проблемных элементов.
7. `run_simulation({ mode: "op" | "dc" | "tran" | "ac", options })` — запускает расчёт и 
возвращает узловые значения или прореженный массив точек (чтобы не переполнять контекст агента).
8. `read_instrument({ instrumentId })` — возвращает показания виртуального мультиметра или 
ключевые метрики сигнала осциллографа (Vpp, Vrms, частота, фазовый сдвиг).
