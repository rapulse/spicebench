# DECISIONS — Журнал архитектурных решений (ADR)

Зафиксированные решения, которые нельзя менять без явного согласования с автором проекта.

---

### ADR-001: Electron вместо Tauri и чистого Rust GUI
- **Статус:** Принято
- **Контекст:** Требуется клон интерфейса EWB 5.12 (Win95) с одинаковым поведением на Windows 
10/11 и macOS (разработка ведётся на Mac M1) и быстрой итерацией с помощью ИИ-агентов.
- **Решение:** Использовать **Electron + TypeScript + React**.
- **Причины:**
  1. Идентичный движок рендеринга (Chromium) на Windows и macOS — исключает расхождения 
SVG/Canvas и `98.css` между WebKit и WebView2.
  2. Единый язык (TypeScript) на всех слоях и официальный `@modelcontextprotocol/sdk`.
  3. Вес ~100–130 МБ приемлем для инженерного десктопного софта.

### ADR-002: Единый источник правды и `ngspice` в бэкенде (Node Worker)
- **Статус:** Принято
- **Контекст:** При хранении симулятора в Web Worker фронтенда возникает конфликт с MCP: агент 
не может запускать расчёты в headless-режиме, а свёрнутое окно ОС троттлит фоновые воркеры.
- **Решение:** Хранить состояние схемы и запускать `ngspice` в бэкенде (Electron Main / Node 
Worker), оставив Renderer тонким клиентом.
- **Последствия:** Полная поддержка headless-режима для агентов, независимость расчётов от 
состояния окна и простая тестируемость через Vitest.

### ADR-003: Монорепозиторий и сборка MCP раньше GUI
- **Статус:** Принято
- **Контекст:** При разработке с GUI на первом шаге бизнес-логика часто протекает в 
React-компоненты.
- **Решение:** Разделить проект на `packages/core`, `packages/sim`, `packages/mcp` и 
`apps/desktop`. Полностью реализовать и покрыть тестами `core` -> `sim` -> `mcp` до начала 
вёрстки Electron.
- **Последствия:** Гарантированная чистота архитектуры и возможность отлаживать сложную логику 
быстрыми юнит-тестами без поднятия окна.

### ADR-004: Целочисленная логическая сетка в модели данных
- **Статус:** Принято
- **Контекст:** Хранение экранных пикселей в JSON приводит к ошибкам округления при зуме, 
разрывам контактов на 1 px и затрудняет размещение деталей для ИИ-агентов.
- **Решение:** В `packages/core` координаты компонентов, пинов и вершин проводов хранятся 
исключительно в целых числах (шаг сетки = 1 единица). Масштабирование в пиксели выполняется 
только в Renderer.

### ADR-005: Открытый формат `.ewb.json` вместо реверса бинарников `.ewb`
- **Статус:** Принято
- **Контекст:** Формат файлов EWB 5.x является закрытым проприетарным бинарным форматом.
- **Решение:** Использовать человекочитаемый версионируемый JSON (`.ewb.json`) как основной 
формат проекта, дополнив его экспортом (и позже импортом) стандартных SPICE-нетлистов (`.cir`).

### ADR-006: Clean-room реализация на открытых компонентах
- **Статус:** Принято
- **Контекст:** Electronics Workbench — проприетарный продукт National Instruments (не MIT).
- **Решение:** Использовать `ngspice` (лицензия Modified BSD) как расчётное ядро и открытые 
SPICE-модели (от производителей, KiCad и др.). Оригинальные бинарники, ассеты и товарные знаки 
NI/EWB в репозитории не используются.
