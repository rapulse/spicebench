# ARCHITECTURE — Архитектура SpiceBench

## 1. Общая схема слоёв

Приложение строится по принципу **единого источника правды в бэкенде** (Electron Main / 
Node.js). Графический интерфейс выступает тонким клиентом, а MCP-сервер работает с тем же 
состоянием, что и пользователь.

```text
┌──────────────────────────────────────────────────────────┐
│  apps/desktop (Renderer: React + TypeScript + 98.css)    │
│  - SVG-холст схемы (зум, пан, перевод сетки в пиксели)   │
│  - Плавающие окна приборов (Canvas: осциллограф, Боде)   │
└────────────────────────────┬─────────────────────────────┘
                             │ Typed IPC (Preload Bridge)
┌────────────────────────────▼─────────────────────────────┐
│  Electron Main Process / Headless Node Service           │
│                                                          │
│  ┌──────────────────────┐    ┌────────────────────────┐  │
│  │ packages/core        │◄───│ packages/mcp           │  │
│  │ - JSON Circuit Graph │    │ - stdio + HTTP MCP API │  │
│  │ - Manhattan Router   │    │ - AI Agent Tools       │  │
│  │ - Undo/Redo + Valid. │    └───────────┬────────────┘  │
│  └──────────┬───────────┘                │               │
│             │ JSON Graph                 │               │
│  ┌──────────▼────────────────────────────▼────────────┐  │
│  │ packages/sim (Node Worker Thread)                  │  │
│  │ - JSON -> SPICE Netlist Generator                  │  │
│  │ - ngspice-45.2 WASM in worker_threads (ADR-007)    │  │
│  │ - Results Parser (.op / .dc / .tran / .ac)         │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

## 2. Зоны ответственности пакетов

### `packages/core`
Чистая доменная логика без привязки к платформе:
- **Circuit Schema (Zod):** валидация и сериализация проекта (`.ewb.json`).
- **Graph Engine:** мутации компонентов и проводов, вычисление электрических узлов (net 
extraction), авторазбиение провода при подключении в середину (junction dot).
- **Manhattan Router:** ортогональная трассировка сегментов по дискретной целочисленной сетке.
- **Command Stack:** детерминированный Undo/Redo.
- **Topology Validator:** быстрая предпроверка схемы до запуска SPICE с возвратом 
структурированных кодов ошибок.

### `packages/sim`
Изолированный расчётный контур:
- **Netlist Compiler:** перевод логических узлов, компонентов и подключённых приборов в 
корректный SPICE-нетлист (`.cir`).
- **Worker Isolation:** ngspice (WASM, `eecircuit-engine`) живёт в отдельном `worker_threads`, чтобы
тяжёлые или расходящиеся расчёты не блокировали Event Loop и UI. По таймауту воркер
принудительно завершается и пересоздаётся (ADR-007). В Electron воркер собирается отдельным
бандлом `dist-electron/ngspice-worker.js`.
- **Result Normalizer:** извлечение узловых напряжений, токов ветвей и массивов точек для 
осциллографа и плоттера Боде.

### `packages/mcp`
Интерфейс для ИИ-агентов поверх `core` и `sim`:
- Поддерживает два транспорта: **Streamable HTTP** (когда запущено десктопное приложение и нужна 
живая отрисовка) и **stdio** (для прямого запуска агентом в headless-режиме).
- При любом изменении схемы через MCP генерирует событие, на которое подписан Electron Main для 
мгновенного обновления окна Renderer.

### `apps/desktop`
Настольная оболочка на Electron:
- **Main:** жизненный цикл окна, файловые диалоги, хранение активного состояния 
`CircuitController`, оркестрация `sim` и `mcp`.
- **Preload:** строго типизированный `contextBridge` API (без `nodeIntegration` в Renderer).
- **Renderer:** визуализация ретро-интерфейса Win95 (`98.css`), обработка событий 
мыши/клавиатуры на холсте и рендер приборов.

## 3. Потоки данных
1. **Действие пользователя:** Renderer отправляет команду по IPC -> Main применяет её через 
`packages/core` -> Main возвращает обновлённый снапшот/дифф -> Renderer перерисовывает холст.
2. **Действие ИИ-агента:** MCP-клиент вызывает инструмент -> `packages/mcp` мутирует состояние 
через `CircuitController` -> Main шлёт IPC-событие `circuit:updated` в Renderer -> пользователь 
видит изменения в реальном времени.
3. **Запуск симуляции:** при включении тумблера питания (или вызове MCP `run_simulation`) 
`packages/core` валидирует топологию -> `packages/sim` генерирует нетлист и считает в воркере -> 
результаты передаются приборам и/или агенту.

## 4. Кроссплатформенная разработка и сборка
- **Локальная разработка:** macOS Apple Silicon (M1).
- **Целевые платформы:** Windows 10/11 (x64, опционально arm64) и macOS (arm64 + x64).
- **Сборка релизов:** автоматическая матрица в GitHub Actions (`windows-latest` + 
`macos-latest`) через `electron-builder`.
- **Проверка Windows-сборки на Mac M1:** виртуальная машина Windows 11 ARM (UTM / Parallels) или 
физический ПК с Windows 11.
