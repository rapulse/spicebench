# Стартовый промпт для новой сессии SpiceBench

> Скопируй всё ниже в новый чат с агентом (рабочая папка `/Users/master/Projects/spicebench`).

---

Ты продолжаешь разработку **SpiceBench**: это десктопный симулятор электронных схем с интерфейсом
Electronics Workbench 5.12 (Windows 95). Внутри Electron + React, расчётное ядро ngspice, встроенный
MCP-сервер для ИИ-агентов.

Главная цель этой сессии — **интерфейс, совпадающий с оригинальным EWB 5.12**: внешний вид, состав и
порядок кнопок, тип элементов управления, поведение окон. Пользователи знают оригинал и будут путаться
при любом расхождении. Вторая цель — закрыть пробелы бэкенда, которые найдутся при сверке с
оригиналом (список ниже), не нарушив уже проверенную точность расчётов.

## 1. Что уже есть и что нельзя ломать
- Расчёт: **ngspice-45.2 (WASM, `eecircuit-engine@1.9.0`)** в `worker_threads` Electron Main, таймаут
  5 с (ADR-007). Самописного решателя больше нет. **Никакой физики и выбора векторов в Renderer.**
- «Power On» = `window.spicebenchApi.runSimulation()` без аргументов. Бэкенд сам выполняет нужные
  анализы (op/tran/ac) и отдаёт `SimulationSummary.instruments[componentId]` (`InstrumentData` из
  `@spicebench/sim`). Поле `status`: `ok | not_connected | no_data | invalid`; при статусе не `ok`
  значения равны `null`. **Показывать «нет измерения», никогда не рисовать 0.**
- Настройки приборов: окно (`InstrumentState`) и `component.params` синхронизирует `CircuitSession`
  (ADR-011). Новые ручки прибора добавлять в схему состояния (`packages/core/src/schema/instrument.ts`),
  в `instrument-settings.ts` (если они влияют на расчёт) и в `INSTRUMENT_SETTING_KEYS`.
- После изменения настроек прибора при включённом питании UI должен снова вызвать `runSimulation()`.
- MCP: только Streamable HTTP `http://127.0.0.1:3100/mcp`, сервер на клиента, только loopback (ADR-010).
- Значение AC-источника — **RMS** (ADR-012, подтверждено `Image-1 2.jpeg`).
- Проверки: `pnpm typecheck && pnpm lint && pnpm test` (сейчас 22 файла, 172 теста, все зелёные).
  Живая проверка бэкенда через MCP на собранном приложении: `pnpm --filter @spicebench/desktop build`,
  затем `./apps/desktop/node_modules/.bin/electron ./apps/desktop/dist-electron/main.js` и
  `node .tmp/live-instruments-check.mjs` (скрипт лежит в `.tmp/`, его можно править).

## 2. Задача A — интерфейс как в EWB 5.12 (основная)
Сверить с `Image-1.jpeg` / `Image-1 3.jpeg` и привести к оригиналу. Что видно на скриншотах
(проверь сам):
- **Заголовок и меню:** `File  Edit  Circuit  Analysis  Window  Help`.
- **Верхний тулбар** (слева направо): New, Open, Save, Print | Cut, Copy, Paste | группа поворота и
  отражения, подсхема, графики | кнопка с карандашом (описание или справка?) | Zoom out, Zoom in,
  комбобокс масштаба `80%` | `?`. Справа: **тумблер питания (O/I)** и под ним кнопка **Pause**.
- **Тулбар полок деталей** (иконки со стрелкой ▼, открывают плавающую полку): Favorites, Sources,
  Basic, Diodes, Transistors, Analog ICs (`ANA`), Mixed ICs (`MIXED`), Digital ICs (`DIGIT`), Logic
  Gates, Digital, Indicators, Controls, Miscellaneous (`M`), Instruments. Точный порядок и иконки
  сверить по скриншоту.
- **Полка открывается плавающим окном** («Sources» с крестиком), а не вкладками. Состав полки Sources
  на скриншоте шире нашего каталога (см. задачу B).
- **Вид схемы:** белый холст, подписи номиналов синим в формате EWB (`1.5 k Ohm`, `240 mH`,
  `10 V/1 kHz/0 Deg`, `12 V`, `1 mho`), точки соединений — чёрные кружки, провода — тонкие чёрные;
  провод к осциллографу цветной (красный — канал A).
- **Окно осциллографа** (`Image-1 3.jpeg`): экран с сеткой и двумя перетаскиваемыми курсорами (1 —
  красный, 2 — синий), горизонтальный скроллбар под экраном, панель отсчётов `T1 VA1 VB1 | T2 VA2 VB2
  | T2-T1 VA2-VA1 VB2-VB1`. Группы: **Time base** (`0.10ms/div` со спином, `X position`, кнопки
  `Y/T  B/A  A/B`), **Trigger** (Edge ↑/↓, `Level`, `Auto  A  B  Ext`), **Channel A / Channel B**
  (`10 V/Div` со спином, `Y position`, `AC  0  DC`), кнопки `Reduce`, `Reverse`, `Save`.
- Мультиметр, генератор и Боде: сверить с оригиналом (скриншотов этих окон пока нет — **спроси у
  пользователя**, прежде чем выдумывать вид).
- Существующие `TODO(ui)` в коде: шкала фазы в градусах у Боде (`BodePlotterPanel.tsx`), вид
  состояний «нет измерения» и «Err» у мультиметра (`MultimeterPanel.tsx`). Фолбэк создания состояния
  прибора в `App.tsx handleComponentDoubleClick` убрать: состояние создаёт сессия.

Если для точного совпадения нужно то, чего бэкенд не даёт (курсоры, режимы B/A и A/B, AC-развязка
канала), **не считать это в Renderer**. Добавить поле в `InstrumentData` и посчитать в
`packages/sim/src/instruments/instrument-data.ts`, с тестом.

## 3. Задача B — пробелы бэкенда, найденные по скриншотам (согласовать с пользователем)
1. **Индикаторы Voltmeter и Ammeter на схеме** (`Image-1 2.jpeg`: прямоугольники с показаниями
   `6.995 V`, `4.670 mA` прямо на холсте). Это компоненты полки Indicators, а не окно мультиметра;
   у нас их нет. Нужно: типы в `core`, компиляция (10 МОм / 0 В), DC/AC-режим, данные в
   `instruments` (переиспользовать логику мультиметра), отрисовка на холсте, тесты.
2. **Источники полки Sources**, которых нет в каталоге (по скриншоту, сверить): AC-источник тока,
   четыре управляемых источника (VCVS, VCCS, CCVS, CCCS: ромбы, на схеме «1 mho»), Vcc/Vdd,
   генератор тактовых импульсов, AM/FM-источники, PWL, FSK, полиномиальный и нелинейный зависимые.
   Каждый: тип в `core`, строка в `NetlistCompiler`, тест на ngspice против аналитики.
3. **Непрерывный прогон и Pause.** В EWB `.tran` идёт непрерывно, пока включено питание
   (на скриншоте T1 = 77 мс при развёртке 0.1 мс/дел, экран прокручивается). У нас сейчас один прогон
   на одно окно (10 делений × timebase). Нужно решение (ADR): чанки `.tran` с продолжением от
   последнего состояния или длинный прогон с подкачкой, плюс кнопка Pause.
4. **Число делений экрана осциллографа** (`SCOPE_DIVISIONS = 10`) сверить с оригиналом.
5. **Опорный уровень dB мультиметра** (`DB_REFERENCE_V = 1`) и **амплитуда генератора**
   (пиковая относительно COM) — сверить с оригиналом.

## 4. Прочие хвосты (ROADMAP 9.3б, 9.5 и HANDOFF)
- 9.3б: после UI-работ вручную пройти «Power On» на делителе, RC, RLC и схеме из `Image-1 2.jpeg`.
- 9.5: пробная сборка `pnpm --filter @spicebench/desktop pack` (macOS) и проверка, что ngspice

- `README.md`: в нём есть незакоммиченные правки пользователя (раздел «Дополнительно» с `/sse`,
  `localhost:3100/sse`, XSPICE). Сначала спросить разрешения, потом привести в соответствие
  с ADR-008/010/012.
- `packages/mcp`: `dist/cli.js` после `tsc` скорее всего не запустится в чистом Node (импорты без
  расширений). Проверить и починить сборку headless MCP (stdio).
- MCP: нет токена авторизации (ADR-010); конфиги Claude Desktop (`mcp-remote`) и Antigravity не
  проверены на реальных клиентах; `NativeNgspiceEngine` не проверен (нет ngspice CLI).

## 5. Правила работы
- Сначала сверка с эталоном, потом код. Не уверен, как выглядит или ведёт себя элемент в EWB —
  спроси пользователя (он может прислать скриншот), не выдумывай.
- Ни одного «нуля по умолчанию» на месте отсутствующего измерения.
- После каждого пункта: `[x]` в `docs/ROADMAP.md`, обновить профильную wiki, при отступлении — ADR.
- Отчитываться явно: «проверено (команда/вывод)», «предполагаю», «не сделано».
- Коммитить только по команде пользователя. В коммит брать только свои изменения (проверять
  `git status` перед `git add`; чужие правки, например в `README.md`, не захватывать).
- В конце сессии: `pnpm typecheck && pnpm lint && pnpm test`, перезаписать `docs/HANDOFF.md`
  (до 60 строк), обновить этот файл (`next-chat.md`), если остались задачи.
